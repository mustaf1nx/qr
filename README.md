# Event Pass

Система регистрации через Instagram Direct и одноразовых QR-пропусков. FastAPI + PostgreSQL + React/TypeScript. Интерфейс на русском языке.

## Возможности

- Мероприятия: необязательные даты входа, вместимость или неограниченная выдача, уникальная команда Direct, переключатель проверки подписки.
- Один билет на пару «Instagram Scoped ID + мероприятие»; 256-битный случайный QR-токен.
- Атомарное погашение и журнал попыток входа; отзыв билетов; ручная выдача организатором.
- Камера на телефоне через ZXing, ввод ссылки вручную, PWA. Для проверки всегда нужен интернет.
- Организаторы и сотрудники сканера; Argon2-пароли, HttpOnly-сессии, CSRF-проверка, ограничение попыток входа.
- Webhook Meta с HMAC-подписью, проверкой аккаунта, дедупликацией по message ID, сохраняемой очередью и повторной отправкой.

## Локальный запуск

Требуются Python 3.12+, uv и Node.js 22+. Для рабочей эксплуатации используйте PostgreSQL. SQLite предназначен только для локальной демонстрации.

```powershell
Copy-Item .env.example .env
# В .env: DATABASE_URL=sqlite:///./eventpass.db
# COOKIE_SECURE=false
# ADMIN_PASSWORD=<свой случайный пароль не короче 12 символов>
uv sync --frozen
cd frontend
npm ci
npm run build
cd ..
uv run alembic upgrade head
uv run python -m app.bootstrap
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Откройте http://localhost:8000. Начальных мероприятий и фиктивных гостей нет. Первый организатор создаётся из ADMIN_USERNAME/ADMIN_PASSWORD при первом запуске; последующее изменение переменных не меняет существующий пароль.

Docker Compose: укажите POSTGRES_PASSWORD и ADMIN_PASSWORD в `.env`, затем `docker compose up --build -d`. База хранится в постоянном томе.

## Railway

1. Развернуть официальный шаблон PostgreSQL.
2. Подключить репозиторий к сервису приложения; Dockerfile собирает интерфейс и сервер в один контейнер.
3. Задать DATABASE_URL через ссылку `${{Postgres.DATABASE_URL}}`, ADMIN_USERNAME, случайный ADMIN_PASSWORD, COOKIE_SECURE=true.
4. Создать HTTPS-домен и задать его в PUBLIC_BASE_URL без завершающего `/`.
5. Задать Instagram-переменные из `.env.example`, когда приложение Meta готово.

`/health` проверяет подключение к базе. Схема обновляется Alembic перед стартом. Используется одна реплика приложения; запуск миграций нескольких реплик одновременно не поддерживается. Настройте резервные копии PostgreSQL в Railway и проверьте восстановление до мероприятия.

## Подключение Meta

Нужен профессиональный аккаунт Instagram и приложение Meta с Instagram Login. Разрешения: `instagram_business_basic`, `instagram_business_manage_messages`; для гостей вне ролей приложения нужен соответствующий Advanced Access/App Review.

Переменные:

| Переменная | Назначение |
| --- | --- |
| META_APP_SECRET | App Secret для проверки подписи webhook |
| META_VERIFY_TOKEN | Собственная случайная строка для подтверждения webhook |
| META_ACCESS_TOKEN | Токен профессионального аккаунта |
| META_ACCOUNT_ID | Instagram ID принимающего аккаунта |
| META_API_VERSION | Версия Graph API; сверить с поддерживаемой версией приложения |
| INSTAGRAM_USERNAME | Имя аккаунта без @ |

Webhook: `https://<домен>/webhooks/instagram`, событие `messages`. QR афиши открывает `https://ig.me/m/<username>`. Гость сам отправляет команду мероприятия, например «БИЛЕТ». API профиля запрашивает `username,is_user_follow_business`. Ошибка или отсутствующее поле не трактуется как отсутствие подписки.

Токен подключается серверной переменной, OAuth-экран и автоматическое обновление токенов в этой версии не реализованы. Отслеживайте срок токена в Meta и заменяйте до истечения. Для App Review подготовьте собственные публичные страницы политики конфиденциальности, удаления данных и запись пользовательского сценария. Не публикуйте шаблон юридического текста без реквизитов организатора.

Официальные справочники: [Meta User Profile API](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/user-profile), [Meta Instagram API collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api), [Railway Dockerfiles](https://docs.railway.com/builds/dockerfiles).

## Проверки

```powershell
uv run pytest -q
cd frontend
npm run build
```

CI запускает тесты на отдельной PostgreSQL: конкурентная выдача на последние места, повторная выдача одному гостю, одновременное погашение, неверная подпись webhook, повтор webhook, роли, отзыв, сроки и CSRF. Тесты используют TEST_DATABASE_URL (по умолчанию локальный test.db) и пересоздают схему: никогда не задавайте в TEST_DATABASE_URL адрес рабочей базы. На SQLite PostgreSQL-тест выдачи пропускается.

## Эксплуатационные ограничения

- Код QR можно переслать: владелец ссылки может использовать его первым. Для именного входа сотрудник должен сверить личность.
- Отзыв не возвращает место в лимит: вместимость ограничивает общее число выданных билетов.
- Выдача вручную обходит подписку. Указывайте исходный IGSID гостя; вымышленный ID может привести к второму билету после обращения через Direct.
- Доставка Direct имеет семантику at-least-once. При сбое между принятием сообщения Meta и сохранением результата возможна повторная отправка той же ссылки, но не создание второго билета.
- Повторные отправки прекращаются после восьми ошибок или 23 часов. Счётчик виден в разделе подключения. Гость может отправить команду заново.
- Проверка подписки является настройкой мероприятия; соответствие условиям Meta организатор проверяет перед запуском. Можно включить добровольную подписку.
- Не храните секреты в Git. Не включайте access logs с путями билетов. Ограничьте доступ к логам прокси, где могут присутствовать URL.
- Персональные данные: IGSID, username, статус подписки, билет, история входов. Организатор должен установить срок хранения и процесс удаления; автоматическая политика хранения в этой версии не включена.
- Камеру необходимо проверить на реальных iPhone/Android по HTTPS; эмуляция и API-тесты это не заменяют.
