# Event Pass — Zein Academy

Открытая выдача одноразовых QR-билетов без аккаунтов, анкет и подключения Meta. FastAPI + PostgreSQL + React/TypeScript.

## Сценарий гостя

1. Общий QR открывает `/register/{event_id}`.
2. Гость нажимает «Открыть Instagram», затем возвращается на страницу.
3. «Получить билет» создаёт персональный QR. Подписка добровольная и **не проверяется**; загрузка обозначает создание билета.
4. Сотрудник сканирует QR в защищённой панели. Билет атомарно погашается, повторный проход отклоняется.

Ограничения «один человек — один билет» нет. Повторный HTTP-запрос с тем же случайным `request_id` возвращает прежний билет: это защита от двойного клика/потери ответа, а не идентификация человека. Новый запрос выдачи может создать ещё один билет. Вкладка запоминает последний билет и предлагает запросить следующий. Учётная запись гостю не нужна; при недоступном sessionStorage выдача работает, но восстановление после закрытия вкладки не гарантируется.

Сервер не утверждает, что переход в Instagram или подписка состоялись. Клиент фиксирует нажатие кнопки только для последовательности экранов; напрямую вызвать публичную выдачу также возможно. Именной контроль, ограничения выдачи одному человеку и защита от автоматизированных запросов не входят в текущий сценарий.

## Панель организатора

- Мероприятия: необязательные даты, вместимость или неограниченная выдача.
- Список билетов, статистика, история входов; отзыв неиспользованных билетов.
- Ручная выдача без Instagram ID; имя необязательно.
- Раздел «QR для гостей»: общий QR для афиши и ссылка на выдачу.
- Роли организатора и сканера; Argon2-пароли, HttpOnly-сессии, CSRF-проверка.
- Камера через ZXing, ввод ссылки вручную, PWA. Проверка входа требует интернета.

Старый QR, открывающий Instagram Direct, нужно заменить общим QR регистрации. Ранее выданные персональные билеты сохраняют действительность в пределах их статуса и сроков.

## Локальный запуск

Python 3.12+, uv, Node.js 22+. PostgreSQL для рабочей эксплуатации; SQLite — только предпросмотр.

```powershell
Copy-Item .env.example .env
# .env: DATABASE_URL=sqlite:///./eventpass.db
# PUBLIC_BASE_URL=http://localhost:8000
# COOKIE_SECURE=false
# ADMIN_PASSWORD=<случайный пароль от 12 символов>
# INSTAGRAM_USERNAME=zein.academy
uv sync --frozen
cd frontend
npm ci
npm run build
cd ..
uv run alembic upgrade head
uv run python -m app.bootstrap
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Первый организатор создаётся из ADMIN_USERNAME/ADMIN_PASSWORD. Изменение переменной впоследствии не сбрасывает существующий пароль. Мероприятия создаются в панели `/`; гостям — `/register/{id}`, сотрудникам — `/scanner`.

Docker Compose: задайте POSTGRES_PASSWORD и ADMIN_PASSWORD в `.env`, затем `docker compose up --build -d`.

## Railway

Dockerfile собирает сервер и интерфейс в одном контейнере. Переменные: DATABASE_URL=`${{Postgres.DATABASE_URL}}`, ADMIN_USERNAME, ADMIN_PASSWORD, COOKIE_SECURE=true, PUBLIC_BASE_URL=https://ваш-домен, INSTAGRAM_USERNAME=zein.academy. Для текущей выдачи **META_* не нужны**.

Миграции запускаются перед сервером; `/health` проверяет базу. Используется одна реплика. Настройте резервные копии PostgreSQL и проверьте восстановление до мероприятия. Адреса проекта — в DEPLOYMENT.json.

Исходный адаптер Meta оставлен для совместимости, но в текущем сценарии не используется. Поле require_follow применяется только к этому адаптеру; публичная выдача его не использует и сохраняет статус подписки как неизвестный (`null`).

## Проверки

`uv run pytest -q` и `cd frontend; npm run build`.

CI выполняет тесты на PostgreSQL: конкурентная выдача и погашение, повторы запросов, выдача без аккаунта, вместимость, сроки, отзыв, роли и CSRF. Локально используется test.db. TEST_DATABASE_URL должен указывать только на отдельную тестовую базу: тесты пересоздают схему. Никогда не используйте рабочую базу. PostgreSQL-тест конкурентной выдачи пропускается на SQLite.

## Эксплуатация

- Человек может получить несколько билетов, каждый действует на один проход.
- QR можно переслать: первым пройдёт предъявивший его человек.
- Отзыв не освобождает место в лимите: вместимость ограничивает общее число выданных билетов.
- Отключение мероприятия закрывает выдачу и вход. Время открытия входа не блокирует предварительную выдачу.
- Не храните секреты в Git и не включайте access logs с персональными URL билетов.
- Сохраняются анонимный ID запроса, билет и история проходов. Ручная выдача может содержать имя; исторические Instagram-билеты сохраняют прежние данные. Автоматическое удаление по сроку хранения не включено.
- Камеру следует проверить на реальных iPhone/Android по HTTPS.
